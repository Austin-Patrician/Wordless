自动化适合**输入、结果和权限边界都能事先写清楚**的重复任务，例如每日摘要、定期检查或一次性提醒。每次触发都会创建一个新的通用工作会话，不会复用某条旧对话的临时上下文。一次性待办、需要人决定何时开始，或要续写已有会话时，改用[任务看板](/docs/tasks/)。

<Prerequisites>
- 已启用至少一个可用模型；运行时模型、工作区、技能和 MCP 仍必须存在且可用
- 提示词中已经写清输入来源、输出位置、失败时要保留什么信息，以及验收标准
- 任务不依赖必须由人在场完成的登录、验证码、澄清或高风险审批
- 了解自动化是本地桌面调度：退出 Wordless 后不会继续在云端运行
</Prerequisites>

## 打开自动化列表

在左侧打开 **自动化**。**计划任务**列出每条自动化的名称、计划和下次运行。关闭开关可保留定义但不调度；播放按钮会立即运行一次，不必等到计划时间。

## 从模板开始

还不想从空白提示词写起时，用 **从模板添加**。模板覆盖每日摘要、提醒和例行整理等起点。选中后仍要核对提示词、模型和权限，再保存。

<ScreenshotFrame src="/images/automations/automation-add-from-template.png" alt="从模板添加自动化" caption="模板只是起点。保存前仍要核对提示词、模型和权限。" />

## 填写一条自动化

当前自动化固定使用 **通用工作**，不需要选择 Agent。选择模型后，再配置工作区、技能、MCP、工具审批和访问范围。

<Steps>
1. 填写名称和提示词。提示词应说明结果格式、输入范围、输出位置、不能做的事和检查标准。
2. 选择模型与思考深度。模型在真正运行时也必须保持启用和已配置状态。
3. 需要本地资料时指定工作区；需要扩展能力时显式加入技能或已连接的 MCP。
4. 选择周期、间隔或单次运行，可选设置生效开始/结束日期；关闭「保存后立即启用」可先保存草稿。
5. 点击保存。缺少名称、提示词或模型，或计划和日期范围不合法时，对应区域会标红并给出错误。
</Steps>

<ScreenshotFrame src="/images/automations/automation-add.png" alt="新建自动化：提示词、技能、权限和计划" caption="填写名称、提示词、模型和工作区，再选择周期、间隔或单次。完全访问和绕过审批会显著标出。" />

<ApprovalCheckpoint risk="high">自动化默认会突出显示「完全访问」和「绕过工具审批」。这两项意味着任务可以在无人值守时继续执行。系统提权、明确禁止的安全规则和不可用资源不会因此被绕过。</ApprovalCheckpoint>

新建自动化默认选择 **完全访问 + 绕过工具审批**，保存时必须确认。若任务只是读取和整理工作区资料，建议改为 **默认访问 + 自动审批普通操作**，并先用「立即运行」验证一次。

<PromptBlock label="每日摘要示例">每天工作日 09:15 读取当前工作区中 `inbox/` 与 `notes/` 过去 24 小时内更新的文件。输出一份 Markdown 摘要到 `reports/daily-brief.md`：列出事项、来源路径、建议优先级和待确认问题。不要删除、覆盖或移动已有文件；如果没有新增内容，写入「今日无新增资料」并说明检查范围。完成前核对每项结论都有来源路径。</PromptBlock>

## 计划、时间窗与恢复

| 配置 | 用途 | 注意点 |
| --- | --- | --- |
| 周期 | 每日、工作日、每周或每月在固定本地时间运行 | 月度日期在不存在的月份不会生成无效日期 |
| 间隔 | 每 N 分钟、小时或天运行 | 适合健康检查或短周期轮询，避免将耗时任务设置得过密 |
| 单次 | 在一个指定日期和时间运行 | 成功调度后不会再次安排，运行后任务会自动停用 |
| 生效日期 | 限定计划何时开始或结束 | 结束日期不能早于开始日期 |

调度器只在 Wordless 桌面进程运行时工作。应用启动或设备恢复后，系统会按当前计划恢复，并只补偿最近一次符合恢复条件的错过运行；它不是云端 SLA 或精确到秒的任务系统。需要绝对准时、即使电脑关机也必须执行的工作，应使用专用服务器调度器。

## 工具审批与访问范围

| 设置 | 运行行为 | 适合场景 |
| --- | --- | --- |
| 每次确认 | 每个工具操作都会等待你处理 | 仍在试运行或会写入重要资料 |
| 自动审批普通操作 | 普通操作继续执行，高风险操作暂停 | 已验证的低风险读取、整理流程 |
| 绕过工具审批 | 普通和高风险工具操作自动通过 | 边界极清晰、结果可回滚且已充分测试的流程 |
| 默认访问 | 将文件工具限制在所选工作区 | 常规本地自动化 |
| 完全访问 | 扩大可用文件和工具范围 | 已明确目标路径与影响范围的任务 |

如果任务使用「每次确认」或在自动审批下遇到高风险动作，运行会进入 `waiting`，需要打开关联会话处理审批或回答问题。

## 检查每次运行

打开 **运行历史**，按状态过滤并展开一条记录。不要只看「已完成」；打开关联会话检查实际产物、来源、工具参数和错误信息。

<ScreenshotFrame src="/images/automations/automation-history.png" alt="自动化运行历史和状态过滤" caption="运行历史可按排队、运行中、等待、已完成、失败等状态过滤。展开一条记录可看到完成时间和关联会话。" />

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| queued | 已到期，等待可用执行槽位 | 同时最多运行 3 个任务，等待即可 |
| running | 正在创建或执行会话 | 打开会话观察工具与输出 |
| waiting | 正在等待审批或用户输入 | 处理审批卡或补充问题，任务才会继续 |
| completed | 会话已结束 | 检查交付物和来源，而不是只依赖状态 |
| failed / cancelled | 执行失败或被取消 | 展开会话或运行记录，修正路径、凭据或提示词 |
| configuration-error | 模型、工作区、技能或 MCP 在运行时不可用 | 恢复资源后再手动运行或等待下次计划 |

<ExpectedResult>得到可重复运行的任务定义，以及一条可追踪的运行链路：计划时间、独立会话、审批/工具过程、最终状态与可检查的输出。</ExpectedResult>

## 常见问题

- **运行没有开始：** 确认任务已启用、Wordless 未退出、当前时间仍在生效日期内；用「立即运行」先验证配置。
- **变成 configuration-error：** 重新启用模型、技能或 MCP，检查工作区是否还可用，然后编辑并保存自动化。
- **任务一直 waiting：** 它需要人处理审批或澄清，改用更明确的提示词，或在充分验证后调整审批模式。
- **结果覆盖了文件：** 在提示词中把输出路径、是否允许覆盖和备份规则写成明确约束；高价值资料保持手动审批。
