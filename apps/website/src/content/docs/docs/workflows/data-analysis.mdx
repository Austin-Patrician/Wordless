## 目标

让研究计划、分维度委派、数据处理和结论验证都出现在会话中，而不是只返回一段无法追溯的结论。

<Prerequisites>
- 已准备 CSV、Excel 或可访问的研究来源
- 明确问题、时间范围、指标定义和输出格式
- 研究所需的网络或文件权限已配置
</Prerequisites>

## 推荐流程

<Steps>
1. 选择 **Data Analysis**，引用数据文件并说明字段含义。
2. 要求 Agent 先生成 research plan，检查研究维度和预期证据。
3. 在研究确认卡点击确认，随后让 Agent 使用同一计划返回的 `confirmationToken` 调用 `research_start`。
4. 观察 `research_delegate` 的每个维度：queued、running、success 或 failed。展开单个研究员查看来源和摘要。
5. 合并结果前要求 Agent 标记矛盾、缺失和无法验证的结论。
6. 导出表格或报告，抽查原始数据行和来源链接。
</Steps>

<PromptBlock>
分析 @survey.xlsx 中的用户留存。先提出研究计划，覆盖数据质量、分群、时间趋势、异常点、业务解释和行动建议六个维度。等待我确认计划后再开始研究。每个结论都附字段、行号或来源；不确定时明确写出假设。
</PromptBlock>

<ApprovalCheckpoint>研究确认令牌会过期，计划更新后必须重新确认并使用新令牌。若 `research_start` 缺少 `confirmationToken`，不要手动重试旧的 analysisId，应重新准备计划。</ApprovalCheckpoint>
<ExpectedResult>研究员分组显示独立状态，最终报告包含方法、证据、限制、结论和下一步，而非只有无来源的数字。</ExpectedResult>

## Wordless 的差异

研究不是一个不可展开的工具卡：Wordless 将计划确认令牌、研究维度、单个研究员来源和最终合并分开呈现。这样可以只重跑失败维度，而不是重复整个分析。

| 场景 | 研究维度示例 | 验收方式 |
| --- | --- | --- |
| 用户留存诊断 | 数据质量、分群、趋势、异常、解释、行动 | 结论附字段、行号或来源 |
| 市场研究 | 规模、竞争、用户、定价、风险、证据 | 每个研究员可独立展开 |
| 失败后继续 | 仅重跑 failed 维度 | 已成功维度不重复消耗 |

## 失败恢复

确认过期：重新生成计划并点击确认；工具仍失败：展开失败的研究员查看原始错误，缩小范围或修正字段名后重新开始。网络研究失败不应阻塞本地数据质量扫描。
