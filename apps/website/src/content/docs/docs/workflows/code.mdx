## 目标

让 Agent 在明确范围内完成代码变更，并用测试、差异和失败日志证明结果。

<Prerequisites>
- 工作区是干净分支或已知的本地改动已记录
- 明确修改范围、不能改动的目录和验收命令
- 需要执行的包管理器、运行时和凭据已经可用
</Prerequisites>

<Steps>
1. 引用相关文件或文件夹，先要求 Agent 阅读并总结现状。
2. 给出行为目标、边界条件和测试命令；要求先列计划。
3. 采用手动审批，审阅写入文件和命令的路径、参数与副作用。
4. 要求 Agent 运行聚焦测试，再运行项目级检查。
5. 查看 diff，确认没有生成物、密钥或无关重构后再提交。
</Steps>

<PromptBlock>
检查 @apps/desktop/src/renderer/features/thread/。修复消息列表定位问题。先解释当前 Virtuoso 滚动模型和失败原因，再提出最小修改。只改相关源码与测试；运行对应测试并报告失败日志。不要执行 git reset、删除文件或访问工作区外路径。
</PromptBlock>

<ApprovalCheckpoint risk="high">终端命令可能修改文件、安装依赖或访问网络。每次高风险命令都确认工作目录、命令参数和预计输出。</ApprovalCheckpoint>
<ExpectedResult>会话包含计划、修改文件清单、测试结果和剩余风险；最终差异可被人工逐行审阅。</ExpectedResult>

## Wordless 的差异

代码 Agent 的关键不是“能写代码”，而是把每个命令、权限、差异和测试结果对齐到同一个任务。Wordless 的对话输入区可以用 `@` 精确引用目录，审批卡显示真实命令，失败后仍保留原始日志，方便从中断点继续。

| 场景 | 重点能力 | 验收方式 |
| --- | --- | --- |
| 定位回归 | `@` 范围、代码搜索、原始日志 | 先解释原因，再产生最小差异 |
| 实现功能 | 计划、编辑、测试、审阅 | 聚焦测试和项目检查均有记录 |
| 受控命令 | 默认访问、审批、一次性提权 | 每条命令的目录和参数可见 |
